`Advisor` 类型：`id / name / nameZh / faction / description / descriptionZh / image / actions[]`；行动类型 `AdvisorAction`：`id / title / titleZh / subtitle / subtitleZh / unavailableSubtitle / unavailableSubtitleZh / condition / effect / description / descriptionZh`。顾问级别没有解锁条件字段，**解锁与失活全部由事件改写 `advisorPool` / `activeAdvisors` 实现**。

### 1.2 顾问行动如何结算

```ts
// AdvisorPanel.tsx:39-54（实际结算入口）
if (s.actionsLeft <= 0 || !action.condition(s)) return {};
const newState = action.effect(s);
return { ...newState, actionsLeft: s.actionsLeft - 1 }; // 顾问行动花费 1 AP
```

1. **费用固定 1 AP**，由 UI 支付，不由选项效果处理。
2. **条件在扣费前检查**：`actionsLeft <= 0` 或 `condition(state)` 为假时点击无效，不扣 AP、不进冷却。
3. **共享冷却**：现有 50 个行动成功执行后一律写入 `advisorActionTimer = 6`。**没有分派系、分顾问的独立冷却**；3 个槽位扩大的是可选方案，不是行动额度；换人不重置全局冷却。
4. **条件不满足的提示**来自 `unavailableSubtitle(state)` / `unavailableSubtitleZh(state)`；AP 不足由界面生成「行动点数不足 / Insufficient AP」，与选项条件无关（`selectors.ts:443-460`）。
5. 顾问行动通常不打开事件；两个例外会把 `currentEvent` 指向后续链——拉蒙·佛朗哥的「竞选总统」（竞选事件链）与佩罗、桑蒂利安的最后一次「推动方案」（经济改造路线的开始事件）。

### 1.3 选项条件的九种形态

现有 **50 个选项**中，**41 个的条件只有共享冷却一项**；只有 9 个选项带额外门槛：

| 形态 | 条件表达式 | 使用该条件的选项 |
| --- | --- | --- |
| A 共享冷却 | `state.advisorActionTimer <= 0` | 其余 41 个选项 |
| B 资源门槛 | `state.advisorActionTimer <= 0 && state.resources >= 2` | 阿斯卡索「地下武装整备」 |
| C 组织前提（否定式） | `state.advisorActionTimer <= 0 && !isOrganizationEstablished(state, 'PRRevS')` | 佩斯塔尼亚「筹备政党」 |
| D 日志前提 | `state.advisorActionTimer <= 0 && isAlianzaObreraJournalActive(state)` | 奥罗本、布兰科「推动工人联盟」 |
| E 竞选窗口与次数 | `!state.presidentElectionSeen && state.advisorActionTimer <= 0 && (state.ramon_franco_campaign_count \|\| 0) < 3` | 拉蒙·佛朗哥「竞选总统」 |
| F 推动配额（2 次） | `state.advisorActionTimer <= 0 && (state.economy?.cooperativePushes ?? 0) < 2 && !isCooperativeRouteOpen(state)` | 佩罗「推动合作社方案」 |
| G 推动配额（3 次） | `state.advisorActionTimer <= 0 && (state.economy?.organicPushes ?? 0) < 3 && !isOrganicRouteOpen(state)` | 桑蒂利安「推动有机工团方案」 |
| H 岗位＋战争＋配额 | `state.advisorActionTimer <= 0 && state.ministers.commerce === 'CNT' && state.civilWarStatus === 'ongoing' && getEconomyCounter(state, 'wartime_trade_monopoly') < 2` | 洛佩斯「实行战时外贸垄断」 |
| I 资源＋配额＋组织 | `state.advisorActionTimer <= 0 && getEconomyCounter(state, 'coal_nationalization') < 2 && state.resources >= 2 && isOrganizationEstablished(state, 'CNT')` | 佩罗「煤炭国有化」 |

含义与依赖：

- **B**：资源不足时条件为假。提示文案只覆盖冷却，不覆盖资源，见 §10。
- **C**：`isOrganizationEstablished(state, 'PRRevS')` 成立后该选项**永久不可用**——它是建党前的筹备行动，PRRevS 成立即完成使命。
- **D**：`isAlianzaObreraJournalActive` 读取 `journal['journal_alianza_obrera'].status === 'active'`，即日志已由「十字路口：无产阶级起义还是反法西斯同盟？」的**选项 A「无产阶级起义！」**开启（它是唯一能把该日志置为 `active` 的入口）。开启时选项 A 自身也会 `workersAllianceProgress +1`（封顶 3），因此顾问的两次「推动工人联盟」是把进度补到 3 的关键来源，`progressMax` 也是 3（`journal/alianza_obrera.ts:19-29`、`events/crossroads_uprising_alliance.ts:33-51`）。
- **E**：`presidentElectionSeen` 一旦为真即锁死；`ramon_franco_campaign_count` 最多累加到 3，之后只能等总统选举链读取该计数。
- **F / G**：两条经济改造路线的「确定性入场券」（设计见 [经济改造方案](./旧文件/经济改造方案.md) §9.3）。推动计数在阈值处夹紧（`ECONOMY_PUSH_LIMITS`），因此配额用尽后条件自然为假；已开启对应日志（佩罗看 `active`，桑蒂利安看 `active` 或 `completed`）时选项退役。两者的提示文案都专门区分「方案已经推动完毕」与冷却中，见 §9.2。
- **H**：与政府卡「商业与贸易」（`government_affairs/trade_policy.ts`）的同名选项共用计数器 `wartime_trade_monopoly`（上限 2，见 `ECONOMY_REFORM_CAPS`）。三项门槛缺一不可：商业部 `ministers.commerce === 'CNT'`、内战进行中、垄断未满 2 次；提示文案对这三条分别给出原因，见 §9.2。顾问只写 `advisorActionTimer`，**不写卡牌的 `trade_policy_timer`**，两条路线各自独立冷却。
- **I**：与政府卡「工业与商业」（`government_affairs/industry_policy.ts`）的「接管煤矿」选项共用计数器 `coal_nationalization`（上限 2）。三项门槛缺一不可：垄断未满 2 次、资源 ≥ 2、CNT 已成立；提示文案区分「煤矿已在工人控制之下」与「需要 CNT 已成立，且拥有 2 资源」，见 §9.2。同样只写 `advisorActionTimer`，不写卡牌的 `industry_policy_timer`。

| `applyEconomicOption(state, 计数器, { land?, industry? })` | 经济改造选项的标准写法 | 先按向量动所有权饼，再给计数器 +1；不传向量就只记账（「效果属于行动，记账属于计数器」） |
| `armaments` / `resources` | 军备 / CNT 资源 | 无上限 |

### 1.5 完成状态标注（✅ / 🚧）

顾问名旁的符号是**文档标注**，表示该顾问的内容是否已经定稿，**不是游戏内 UI 元素**，也不影响任何 `condition` 或 `effect`：

| 标注 | 含义 |
| --- | --- |
| ✅ | 该顾问的选项、条件与效果已经确认完成，视为定稿。 |
| 🚧 | 内容未完成：后续还会补充或改写选项，当前选项只是临时集合。 |
| （无标注） | 尚未逐条核对定稿状态。 |

标注不写入 `GameState`，也不参与存档；改判只需修改本表。每当顾问内容变更，必须同步更新对应小节、该派系的顾问索引表、§9 的条件与文案统计以及 §10 的实现观察。

### 设计层：共享冷却的语义

`advisorActionTimer` 是全局单值，任何一位顾问行动后三位一起进入 6 个月冷却。这意味着**任用三位顾问扩大的是可选方案池，而不是行动额度**；换人不能重置冷却。经济改造的两条路线把这一点变成硬约束：佩罗推 2 次加桑蒂利安推 3 次共需 5 个行动窗口，至少横跨 30 个月（见[经济改造方案](./旧文件/经济改造方案.md) §9.3）。顾问与政府卡之间**不共用冷却**：佩罗的「煤炭国有化」、洛佩斯的「实行战时外贸垄断」只写 `advisorActionTimer`，卡牌各自的 `industry_policy_timer` / `trade_policy_timer` 仍由卡牌自己维护。若未来希望「每位顾问独立冷却」，需要把 `advisorActionTimer` 拆成分顾问字段，并同步修改 `effectPreview.ts` 的标签与所有 50 个选项的写入。
